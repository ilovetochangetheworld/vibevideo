# 音频制作

## 默认声音设计

两条输入即可：一条对齐的干声 `narration.wav`，一首用户指定的 BGM。音乐默认固定增益，仅片头片尾淡变。事件音为可选独立来源，不默认添加长音、弦乐、鼓点、空气声或引擎自动合成配乐。

出现“听到别的 BGM”“忽大忽小”时，先排查音轨：旧 `score.wav`、视频内嵌音轨、重复 BGM、浏览器同时播放的其他播放器。不要用一个更小的音量隐藏叠音。确认只有目标 BGM 后再调平衡。

`mix_audio.py` 只映射源视频的 `0:v:0` 和本次混音，丢弃输入视频原有声音；未列入 JSON 的文件不会被混入。不要将来历不清的混合音轨当成“音效”传入。

## 人声

默认 `zh-CN-YunyangNeural`，可从 `rate=+6%`、`pitch=-2Hz` 起试；这是本用户的起始偏好，不是识别原片音色的证据。云希可做更活泼的备选，选型用同一文本试听。

先生成短样确认；逐句合成可准确对齐。`edge-tts` 不是官方 Azure SDK，不能把 Azure 的 `narration-professional` 等 style 直接当成其支持参数。参考：https://github.com/rany2/edge-tts 。音色是否可用由当前服务返回为准。

`cues.json`：

```json
[
  {"start": 0.25, "end": 3.45, "text": "你停住了，隔壁却往前走。"},
  {"start": 3.6, "end": 7.1, "text": "再看另一边，也有人先走了。"}
]
```

`tts.py` 保存逐句 MP3、真实时长报告和完整时间轴 WAV。缓存键包含文本、音色、语速与音调。句子超出时间窗时会报错；增加时间、改短文案或适度加速后重新生成，不截尾字。新片以实际语音时长反推时间线，已有画面可保留时间窗。

## 单 BGM 混音

`mix.json` 中的路径相对于 JSON 文件所在目录：

```json
{
  "video": "renders/raw.mp4",
  "output": "renders/final.mp4",
  "duration": 36,
  "voice": {"file": "audio/voice/narration.wav"},
  "bgm": {"file": "audio/bgm.mp3", "start": 9.72, "rms_db": -28, "fade_in": 0.7, "fade_out": 1.4},
  "effects": [],
  "target_lufs": -16,
  "true_peak_ceiling_db": -2,
  "credit": "配乐名称、作者、来源及实际许可要求"
}
```

- `rms_db=-28` 是音乐音量的起点，不是所有歌曲的固定答案。视人声电平、编曲密度和听感调整；说话费力时优先整体降低 BGM，不自动 duck。曲目自身的动态予以保留。
- `start` 选在合适的乐句；若要对齐片名或揭晓，先检测、试听音乐变化位置，再计算截取起点。不要把本片的 9.72 秒复用到另一首歌。
- 人声默认高通并单独归一化至约 -18 LUFS、真峰 -4 dBTP，只处理人声，BGM 不跟随人声变化。已处理好的人声可以设置 `"filter": "anull"`。
- 声音轨为可选：无旁白时省略 `voice`，无配乐时省略 `bgm`。`effects` 默认为空；只加入确认不含配乐的纯事件音轨。脚本不生成音效。
- 统一响度仅用一个固定总增益；若真峰限制与目标 LUFS 冲突，优先不超峰值，报告实际结果，不为追数值进行全混音动态压缩。
- 输出旁边的 `*-audio/report.json` 列出每条来源、SHA256、曲目截取、实际电平、是否使用视频原声音，以及 `speech_ducking=false`。PCM stems 供分轨试听。报告只能证明技术参数，不证明审美或听感。

## 试听与交付

比较 A/B 时沿用同一段缓存人声和主体画面。不要同时播放两版。播放器切换保留进度、暂停旧音轨；页面中的人声试听与视频也应互斥播放。

检查开头、片名、每个说话进入/退出点以及结尾，重点听音乐是否稳定、人声是否清晰。交付视频至少保留 AAC 立体声；检查最终编码后真峰（预留约 2dB 余量给 AAC），而非只测母带。

用户提供的音乐保留来源记录；不能仅凭链接、网友评论或相似听感声称查到同款。需要来源署名时放在片尾或随片文案，遵守已知许可；不要把歌曲音频装进技能包。
